# Website requirements

- Preserve the user's Blank visual foundation unless a new theme or redesign is requested.
- Every theme must support Simplified Chinese (`zh-CN`), Taiwanese Traditional Chinese (`zh-TW`), Japanese (`ja`), and English (`en`). These are site-wide settings, not theme-specific preferences.
- Use `src/core/i18n` for translations, locale detection, localized URLs, the language switcher, and the `site-locale` storage key. Do not introduce per-theme locale storage or independent translation dictionaries.
- A new theme must mount the shared `LanguagePreference.astro` in its head and `LanguageSwitcher.astro` in its navigation, set HTML `lang`, and build all four locale routes. Preserve the current article and theme route when switching languages.
- All user-facing strings, accessibility labels, status text and SEO descriptions must have all four language versions. `zh-TW` text uses Taiwanese vocabulary and official Taiwanese titles, not a character-by-character conversion. Article translations use the same `translationKey`. Missing article translations must show the Simplified Chinese original with the explicit fallback notice; never pretend it is translated.
- Personal data, social links, projects, collections, and article sources belong in `src/core/data`, `src/core/i18n/content.ts`, and `src/content/blog`. Every theme reads the shared sources through `getSiteContent(locale)`, `socialLinks`, and `getPublishedPosts(locale)`; never maintain copies inside a theme.
- Every theme must mount `src/core/components/SiteIcons.astro` in its head so all themes and languages use the same site favicon and touch icon.
- Every theme must mount `src/core/preferences/ColorModePreference.astro` and `src/core/navigation/SiteNavigation.astro` in its head. `SiteNavigation` mounts `mountSiteFeatures(document, window)` once per page; themes must not call it themselves. Theme-specific page scripts register through `registerThemeRuntime()` from `src/core/themes/runtime.mjs`; shared code in `src/core` never imports from `src/themes`, except `src/core/themes/PageLayout.astro`, which selects each theme's layout at build time. Use the shared `data-site-*` hooks for search, filters, sorting, table of contents, and reading progress. See `docs/THEMES.md` for the contract.
- Keep the light/dark preference when switching themes, languages, or pages. Use the shared legacy `blank-color-mode` storage key; default to the system until a visitor manually chooses light or dark. Do not add an Auto option.
- Put future reusable features and service clients in `src/core`, with theme-specific presentation in `src/themes`. A new theme must explicitly render controls for any feature it offers; sharing logic does not automatically create a UI.
- This public repository is the source for `https://laozhej.github.io/`. Deploy to GitHub Pages through `.github/workflows/deploy.yml` on pushes to `main`. Keep the root URL configuration; do not add a repository-name `base` prefix.
- Keep hosting credentials, environment files, and Sites-specific configuration out of this repository. Preserve upstream copyright notices and licenses.
- Verify all locale routes, cross-language links and narrow-screen controls before publishing an update.
