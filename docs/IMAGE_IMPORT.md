# 图片导入工具

在本机把图片压缩为 WebP、命名、记录来源，并生成站内路径、Markdown 和 HTML 引用。拖拽界面与命令行使用同一个导入模块，不向第三方上传图片，不自动提交或部署网站。

## 拖入图片

在网站源码目录运行（已有依赖时可跳过 `npm ci`）：

```sh
npm ci
npm run images
```

打开终端显示的 `http://127.0.0.1:4318`：

1. 拖入图片，或点击选择；可以一次选择多张。
2. 按需填写每张图片的文件名和图片描述。描述用于替代文字及生成引用。
3. 外部作品填写**原始来源页**；自己拍摄或制作的图片选择「我原创的图片」。作者、许可、原图链接和备注按已知信息填写。
4. 点击「压缩并导入」，复制路径、Markdown 或 HTML；也可以复制整批 Markdown。

同一批图片共用来源信息。来源不同请分批导入。来源清单中的文字会随公开仓库公开，工具不会自动推断或验证作者、许可或是否由 AI 创作。

「已导入的图片」从磁盘读取历史记录，重启后仍可复制引用。导入后需要提交并部署网站，引用才会在正式网址生效。界面支持简体中文、台湾繁体中文、日语和英语，使用公共的 `site-locale` 偏好键。

按 `Ctrl+C` 关闭服务；端口被占用时运行 `npm run images -- --port 4319`。

## 命令行

原创图片：

```sh
npm run image:import -- "/本机路径/我的照片.png" \
  --original \
  --name seaside \
  --alt "海边的傍晚" \
  --creator "作者名字"
```

外部作品：

```sh
npm run image:import -- "/本机路径/illustration.png" \
  --source "https://example.com/original-publication" \
  --source-image "https://example.com/original-image.png" \
  --creator "原作者" \
  --license "按已确认的许可填写" \
  --notes "来源核对说明" \
  --name article-cover \
  --alt "对图片内容的描述"
```

示例 URL 使用时替换为图片的真实来源。

| 参数 | 含义 |
| --- | --- |
| 图片路径 | 可提供多个本地文件路径；含空格的路径加引号 |
| `--original` | 明确标记为自己的原创图片 |
| `--source` | 外部作品必填，原始发布页的 HTTP / HTTPS URL |
| `--source-image` | 可选，原图 URL |
| `--creator` | 可选，作者或摄影者 |
| `--license` | 可选，已知的许可或使用条件；不填就保持空白 |
| `--notes` | 可选，来源说明 |
| `--name` | 可选，文件名前缀；默认使用原文件名 |
| `--alt` | 可选，图片描述，用于生成引用 |
| `--max-size` | 最长边，默认 `1600`，范围 `64–4096` |
| `--quality` | WebP 品质，默认 `82`，范围 `40–100` |
| `--json` | 输出结构化 JSON，方便脚本调用 |
| `--locale` | 提示语言：`zh-CN`（默认）、`zh-TW`、`ja`、`en` |
| `--help` | 显示用法 |

命令行的一批图片共用来源、命名提示和描述。需要不同说明时逐张导入；同名文件由校验码区分。

## 输出与命名

- 图片：`public/images/imported/<名称>-<16位校验码>.webp`
- 来源清单：`src/core/data/imported-images.json`
- 引用示例：`![海边的傍晚](/images/imported/seaside-<校验码>.webp)`

文件名前缀转为小写英文字母、数字和连字符。无法转成英数字的名字（例如纯中文名）使用 `image` 前缀；可手动填写英文名。不记录本机绝对路径。

同一原图、同一压缩参数和同一编码器版本复用首次导入的路径，即使原文件被重命名或重新填写前缀；新增来源合并保留。首次描述保留在历史清单中，重新填写的描述用于本次输出的引用。更改压缩参数生成独立图片，不替换旧引用。

每条记录包含导入时间、原文件名、原图与输出的尺寸/格式/字节数/SHA-256、压缩参数、编码器版本，以及填写的来源、作者、许可和备注。所有主题可引用同一路径。现有主题、游戏、角色等图片的 `ASSETS.json` 保持原来的记录方式，本工具维护新增导入图片。

## 处理边界与恢复

- 支持 JPEG、PNG、WebP、AVIF、静态 GIF；不处理 SVG、动图和多页图片，避免静默丢失动画或页面。
- 每批 `1–20` 张，单张最多 `25 MiB`，整批最多 `50 MiB`，原图不超过 `4000 万`像素。
- 等比缩小、不裁切、不放大，纠正 EXIF 方向、保留透明背景，移除 EXIF/IPTC 等元数据。原文件不修改、不删除，也不自动复制进仓库；请自行保留原始文件。
- WebP 为有损压缩。很小或已高度压缩的图片可能变大，界面如实显示体积变化；可调整参数后另行导入。
- 整批检查和压缩成功后才写入；写入失败清理本次新建图片。已有图片内容与清单冲突、清单损坏时停止，不覆盖已有内容。
- 两个入口通过 `.image-import.lock/` 互斥，正常完成或失败自动清理。如果进程被强制终止，**确认没有导入进程运行后**删除该文件夹即可重试。断电或强制终止可能留下未列入清单的图片；重新导入会接纳相同内容，拒绝覆盖不同内容。

本地网页只监听 `127.0.0.1`，写入需要同源会话令牌。只提供工具文件和清单内的图片预览，不开放整个仓库。不加入 Astro 的公开路由，部署后访客无法访问导入界面。
